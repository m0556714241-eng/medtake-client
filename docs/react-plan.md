# MedTake – תוכנית עבודה לצד ה-React

את הקוד את כותבת בעצמך. התוכנית אומרת **מה** לבנות ובאיזה סדר, **איזה מידע** עובר לאן, ו**איך יודעים שהשלב גמור**. בסוף כל שלב מריצים את האפליקציה ובודקים, ורק אז ממשיכים לשלב הבא.

מסמכים קשורים:
- `screens-and-decisions.md`: המסכים וההחלטות.
- `server-spec.md`: אפיון השרת.
- `medtake-server/docs/FRONTEND-API-GUIDE.md`: כל נתיב בשרת ומה הוא מחזיר.

## בחירת סוג State: כלל אצבע

| סוג | מתי | דוגמאות בפרויקט |
|---|---|---|
| `useState` | מידע מקומי פשוט של קומפוננטה אחת | חלון פתוח/סגור, תצוגה יומית/שבועית, ערכי הפילטרים |
| `useReducer` | מידע מקומי עם כמה פעולות שקשורות זו לזו | (אופציונלי) הפילטרים של מרשמים: חיפוש, סטטוס, צורה ומיון |
| `useContext` | מידע שכל האפליקציה צריכה | המשתמש המחובר וה-Token (`AuthContext`) **בלבד** |
| `useQuery` | מידע שמגיע מהשרת | מטופלים, מרשמים, מנות, סיכום שבועי, התראות |
| `useMutation` | פעולה ששולחת שינוי לשרת | הוספה, עריכה, מחיקה, סימון, חידוש מלאי |

**לא** שמים בקונטקסט רשימות שמגיעות מהשרת. המקום שלהן ב-React Query.

## מפתחות Query (queryKey): להחליט מראש

| מפתח | מה מביא |
|---|---|
| `['me']` | המשתמש המחובר (`/auth/me`) |
| `['patients', filters]` | רשימת מטופלים |
| `['patient', id]` | מטופל אחד |
| `['prescriptions', patientId, filters]` | מרשמים של מטופל |
| `['doses', patientId, from, to]` | מנות בטווח |
| `['doses-summary', patientId, from, to]` | סיכום שבועי |
| `['alerts']` | התראות מלאי |

אחרי כל פעולה מקבלים ב-invalidate את המפתחות שהושפעו ממנה. למשל, אחרי סימון "נלקח": `doses`, `doses-summary` ו-`alerts`.

## שלב 0: הקמה ⏱️ חצי יום

**מה עושים:**
- מתקינים את החבילות: `react-router-dom`, `@tanstack/react-query`, `react-hook-form` ו-`axios`.
- יוצרים את התיקיות: `pages`, `components`, `api`, `types` (כבר קיימת), `context` ו-`routes`.
- יוצרים `.env` עם `VITE_API_URL=http://localhost:3000/api`, וגם `.env.example` עם אותו משתנה. מוודאים ש-`.env` רשום ב-`.gitignore`.
- כותבים `api/api.ts`: מופע axios **אחד** שלוקח את הכתובת מה-ENV, בודק שהמשתנה קיים, ומוסיף לכל בקשה את הכותרת `Authorization` כשיש Token.
- עוטפים את האפליקציה ב-`QueryClientProvider` וב-`BrowserRouter`.

**סיימת כש:** השרת רץ, והאפליקציה מצליחה להביא את `/health` ולהציג את התשובה. אחר כך מוחקים את הבדיקה הזו.

**מכסה מהרשימה:** קובץ ENV, קובץ api מרכזי, כתובת API שלא מפוזרת בקומפוננטות.

## שלב 1: התחברות, ניתוב ו-Header ⏱️ יום

**קומפוננטות:**
- `context/AuthContext`: מחזיק `user`, `token`, `login()` ו-`logout()`.
  - כשהאתר נטען, קוראים את ה-Token מ-localStorage וקוראים ל-`/auth/me`.
  - ביציאה מוחקים את ה-Token ומאפסים את המשתמש.
- `pages/Entrance`: מכיל את `Login` ואת `Register`.
  - שני הטפסים בנויים עם React Hook Form ועם validation.
  - הכפתור מושבת בזמן השליחה.
  - שגיאה 401 או 409 מוצגת כהודעה ברורה.
- `routes/ProtectedRoute`: משתמש בלי Token עובר לעמוד הכניסה. אפשר להעביר `role` כדי לחסום תפקיד אחר.
- `components/Header`: לוגו, שם המשתמש, `NavLink` לפי תפקיד, ו-Logout.
- `pages/NotFound`: עמוד לנתיב שלא קיים.

**ניתוב:**
| נתיב | עמוד | מי |
|---|---|---|
| `/login` | Entrance | כולם |
| `/manager` | Manager | מטפל |
| `/manager/patients/:id` | PatientDetails | מטפל |
| `/my-medicines` | MyMedicines | מטופל |
| `/my-medicines/:date` | MyMedicines (יום מסוים) | מטופל |
| `/` | הפניה לפי תפקיד | מחובר |
| `*` | NotFound | כולם |

**סיימת כש:**
- התחברות כ-`rachel@medtake.dev` מעבירה ל-`/manager`.
- התחברות כ-`avraham@medtake.dev` מעבירה ל-`/my-medicines`.
- אחרי רענון של הדף המשתמש עדיין מחובר.
- Logout מחזיר לעמוד הכניסה.
- `/manager` בלי התחברות מעביר לעמוד הכניסה.
- מטופל שנכנס ל-`/manager` עובר לעמוד שלו.

**מכסה מהרשימה:** התחברות, AuthContext, ניתוב, ProtectedRoute, NavLink, עמוד 404, שני תפקידים.

## שלב 2: עמוד הניהול ⏱️ יום-יומיים

**קומפוננטות:**
- `pages/Manager`: מחזיק את מצב הפילטרים ב-`useState` ומביא את הרשימה עם `useQuery(['patients', filters])`.
- `components/FiltersPatient`: מקבל את הפילטרים ופונקציה לשינוי שלהם ב-props.
- `components/PatientCard`: מקבל `PatientSummary` ב-props.
  - מציג עיגול עם אות, שם, גיל, תאריך הצטרפות, X/Y וצבע, וסמל מלאי נמוך.
  - כולל כפתורי עריכה ומחיקה.
  - לחיצה על הכרטיס מעבירה לעמוד המטופל.
- `components/Modal`: חלון קופץ כללי, שמשמש את כל הטפסים.
- `components/AddPatient`: מקבל `patientId?` ו-`onClose`.
  - במצב עריכה טוען את המטופל וממלא את הטופס עם `reset`.
  - השליחה היא `useMutation`, ואחריה invalidate ל-`['patients']`.
- מחיקה: מבקשים אישור, ואז `useMutation` ו-invalidate.

**ארבעת המצבים:**
| מצב | מה מציגים |
|---|---|
| Loading | "טוען..." |
| Error | הודעה, וכפתור "נסי שוב" |
| Empty | "עדיין אין מטופלים", והחלון של `AddPatient` נפתח אוטומטית |
| Success | הכרטיסים, עם `key={patient.id}` |

**סיימת כש:**
- אפשר להוסיף מטופל, לערוך ולמחוק.
- הרשימה מתעדכנת בלי רענון של הדף.
- החיפוש, המיון והסינון עובדים.
- מטפל חדש רואה את החלון הקופץ.

**מכסה מהרשימה:** רשימה, הוספה ועריכה, טפסים עם validation, React Query, invalidate, מצב ריק, props.

## שלב 3: עמוד מטופל בודד ⏱️ יומיים

**קומפוננטות:**
- `pages/PatientDetails`: לוקח את ה-`id` מ-`useParams`.
- `components/PatientProfile`
- `components/DailyMedicine`: מקבל `patientId?`, `date` ו-`canMark`. **זו אותה קומפוננטה שתשמש בשלב 4.**
- `components/PrescriptionCard`: שם, מינון, צורה, ימים ושעות, מלאי, סמל מלאי נמוך וסטטוס.
  - פעולות: עריכה, חידוש מלאי, שינוי סטטוס ומחיקה.
- `components/FiltersPrescription`: חיפוש לפי שם, סטטוס, צורה ומיון. אפשר עם `useReducer`.
- `components/AddMedicine`: טופס עם React Hook Form.
  - הימים בשבוע: 7 תיבות סימון.
  - השעות: רשימה שאפשר להוסיף לה ולמחוק ממנה, עם `useFieldArray`.
  - המספרים נשלחים עם `valueAsNumber`.
- `components/RefillStock`: שדה אחד, "כמה יחידות להוסיף".

**סיימת כש:**
- אפשר להוסיף מרשם, לערוך, להשהות, לסיים, לחדש מלאי ולמחוק.
- כל פעולה מעדכנת את המסך.
- שגיאות ולידציה מהשרת, מתוך `errors`, מוצגות ליד השדות המתאימים.

**מכסה מהרשימה:** האובייקט המרכזי עם יותר מ-5 שדות, סטטוס וקטגוריה (צורה), חיפוש, סינון ומיון, עריכה.

## שלב 4: התרופות שלי (מטופל) ⏱️ יומיים

**קומפוננטות:**
- `pages/MyMedicines`:
  - המתג יומי/שבועי נשמר ב-`useState`.
  - התאריך נלקח מ-`useParams`. אם אין תאריך, משתמשים בתאריך של היום.
- `DailyMedicine` עם `canMark=true`:
  - סימון מבצע `POST /intakes`, וביטול מבצע `DELETE /intakes/:intakeId`.
  - אחרי כל אחד מהם: invalidate ל-`doses`, `doses-summary` ו-`alerts`.
  - בזמן השליחה הכפתור מושבת, כדי שלחיצה כפולה לא תשלח פעמיים.
  - סרגל "נלקחו X מתוך Y".
- `components/WeeklyMedicine`:
  - מבקש את `/doses/summary` מיום ראשון עד שבת.
  - מציג 7 כרטיסים, ולחיצה על כרטיס עוברת ל-`/my-medicines/<תאריך>`.
- `utils/dates.ts`: פונקציות שמחזירות את תאריך היום ואת ראשון ושבת של השבוע. לבנות את התאריך מהשנה, החודש והיום המקומיים, ולא מ-`toISOString`.

**סיימת כש:**
- אברהם מסמן מנה, הסטטוס משתנה, והמלאי יורד. אפשר לראות את זה גם במסך של רחל.
- ביטול סימון מחזיר את המצב.
- בתצוגה השבועית הצבעים נכונים.

## שלב 7: העלאה לאינטרנט ⏱️ חצי יום
- השרת והמסד עולים ל-Render, לפי `medtake-server/START-HERE.md`.
- `npm run build` של הלקוח מסתיים בלי שגיאות, ואחר כך מעלים את הלקוח ל-Render כ-**Static Site**:
  - **Build:** `npm ci && npm run build`
  - **Publish directory:** `dist`
  - משתנה סביבה: `VITE_API_URL` = כתובת השרת בענן ועוד `/api`.
  - ב-Redirects/Rewrites: `/*` → `/index.html`, כדי שרענון של הדף לא יחזיר 404.
- מוסיפים את כתובת הלקוח ל-`CORS_ORIGIN` של השרת.
- בדיקה ידנית מלאה באתר שבענן.

1. **מה היא עושה?**

3. **מה גורם למסך להתעדכן:** שינוי ב-state, או invalidate שמביא מחדש מהשרת?
